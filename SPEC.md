# DK1 Tick-to-Trade Engine on Zynq — Build Specification

> **Project codename:** `dk1-t2t`
> **One-line pitch:** An FPGA-accelerated tick-to-trade engine for the Danish (DK1) continuous intraday power market. It parses a binary market-data feed, maintains a per-product limit order book in hardware, runs a fair-value taker strategy with pre-trade risk checks, and emits orders, all inside the FPGA fabric of a Zynq-7000 (ZYBO Z7). Every order carries its fabric latency measured in clock cycles.
> **Context:** Final project for *Embedded Real-Time Systems (ERTS)*: SysML/UML HW/SW co-design → requirements → architecture alternatives → design patterns → HLS model + testbench → implementation on ZYBO with at least one HLS IP core.

If you find an ambiguity, choose the simplest deterministic interpretation, write it into `docs/DECISIONS.md`, and apply it to *all* implementations.

5. **Determinism everywhere.** Seeded RNG, integer arithmetic in the trading path, no floating point in C++/HLS core.

## 4. Domain background (keep this short in docs, but correct)

- **Market:** Nord Pool / SIDC continuous intraday, bidding zone DK1 (West Denmark). Products: quarter-hour and hourly delivery periods. **Gate closure for DK: 60 minutes before delivery.** Price tick **0.01 EUR/MWh**, price limits **±9,999 EUR/MWh**, volume tick **0.1 MW** (source: Nord Pool product specifications Nordic & Baltic, Jan 2026).
- **Prices can be negative** (common in DK1 with high wind), so price is signed everywhere.
- **Fundamentals that move intraday prices:** wind/solar forecast revisions vs. the day-ahead forecast; the final imbalance price.
- **This project simulates** quarter-hour products only, and only during the last 2 hours before each product's gate closure (when activity is highest). This is a documented simplification.

## 5. Wire protocol (`proto/`)

All messages are **fixed 32 bytes, little-endian**, transported on a **64-bit AXI4-Stream** as **4 beats** per message. Beat *k* carries bytes `8k..8k+7`; byte *i* of a beat occupies bits `[8i+7:8i]`.

### 5.1 Units

| Quantity | Type | Unit |
|---|---|---|
| `price` | `int32` | 0.01 EUR/MWh (e.g. `-1234` = −12.34 EUR/MWh) |
| `qty` | `uint32` | 0.1 MW (e.g. `25` = 2.5 MW) |
| `ts_ns` | `uint64` | exchange time, ns since Unix epoch (UTC) |
| `order_id` | `uint64` | exchange order reference |
| `product` | `uint16` | product slot `0..P_MAX-1` (§6.2) |

### 5.2 Inbound market-data messages (feed → IP)

Common layout:

| Offset | Size | Field |
|---|---|---|
| 0 | 1 | `type` (ASCII) |
| 1 | 1 | `flags` (bit0 = side: 0 = bid/buy, 1 = ask/sell; bit1 = type-specific) |
| 2 | 2 | `product` |
| 4 | 4 | `seq` (strictly +1 per message, starts at 1) |
| 8 | 8 | `ts_ns` |
| 16 | 8 | `order_id` |
| 24 | 4 | `price` |
| 28 | 4 | `qty` |

| Type | Name | Field usage |
|---|---|---|
| `'A'` | Add order | `order_id`, side, `price`, `qty` |
| `'X'` | Delete order | `order_id` (removes the full remaining qty) |
| `'E'` | Execute | `order_id`, `qty` = executed qty, `price` = trade price (informational) |
| `'M'` | Reduce | `order_id`, `qty` = qty to remove (partial cancel) |
| `'S'` | Product state | `qty` = state code (0 PREOPEN, 1 OPEN, 2 CLOSED, 3 HALT); `price` = ladder anchor; `order_id` = gate-closure time (ns) |
| `'V'` | Fair value | `price` = fair value; `qty` = edge (price units). Emitted by the strategy's slow path, merged into the feed |
| `'H'` | Heartbeat | `flags.bit1 = 1` → **END_OF_SESSION** (must be the last message of every dataset) |

Unused fields are 0. Unknown types are counted (`err_unknown_type`) and skipped.

### 5.3 Outbound records (IP → PS)

All are 32 bytes on 64-bit streams. **Bytes 24..31 (`t_in`, `t_out`) are excluded from golden comparison.**

**`ord_out` stream: `'O'` Order, `'R'` Reject (debug only), `'Z'` End of session:**

| Offset | Size | `'O'` / `'R'` | `'Z'` |
|---|---|---|---|
| 0 | 1 | type | `'Z'` |
| 1 | 1 | flags: bit0 side, bit1 IOC (=1) | 0 |
| 2 | 2 | product | 0 |
| 4 | 4 | `trig_seq` (seq of triggering input msg) | seq of END message |
| 8 | 4 | `client_order_id` (1,2,3,… per session; rejects don't consume IDs) | `msgs_in` |
| 12 | 4 | `price` | `orders_out` |
| 16 | 4 | `qty` (`'R'`: requested qty before clamps) | `first_t_in` |
| 20 | 4 | 0 for `'O'`; reject reason for `'R'` (§6.6) | `last_t_in` |
| 24 | 4 | `t_in` (cycle count, copied from input TUSER) | `t_in` |
| 28 | 4 | `t_out` (written by `axis_ts_out` probe) | `t_out` |

`TLAST` is asserted **only** on the last beat of `'Z'`, so the S2MM DMA completes one transfer per session.

**`dbg_out` stream: `'B'` BBO record** (only when `CTRL.dbg_en = 1`; one per input message of type A/X/E/M/S/V with a valid product):

| Offset | Size | Field |
|---|---|---|
| 0 | 1 | `'B'` |
| 1 | 1 | bit0 bid_valid, bit1 ask_valid |
| 2 | 2 | product |
| 4 | 4 | seq of input msg |
| 8 | 4 | best_bid price (0 if invalid) |
| 12 | 4 | best_bid qty (0 if invalid) |
| 16 | 4 | best_ask price (0 if invalid) |
| 20 | 4 | best_ask qty (0 if invalid) |
| 24 | 8 | `t_in`, `t_out`-slot (ignored) |

A `'Z'` record is also written to `dbg_out` (with `TLAST`) when `dbg_en = 1`.

### 5.4 Deliverables for M1

## 6. Exact processing semantics (shared by Python ref, C++ core, HLS, ARM)

### 6.1 Compile-time parameters (`hls/src/core/config.hpp` + mirrored in `ref/model.py`)

| Name | Default | Meaning |
|---|---|---|
| `P_MAX` | 8 | product slots |
| `SETS` | 1024 | order table sets |
| `WAYS` | 4 | order table associativity → capacity 4096 live orders |
| `W` | 1024 | price ladder levels per side per product |
| `LADDER_TICK` | 10 | price units per ladder level (0.10 EUR/MWh) → window ±51.2 EUR/MWh around anchor |

### 6.2 State

- `state[p]` ∈ {PREOPEN=0, OPEN=1, CLOSED=2, HALT=3}; initial PREOPEN. `anchor[p]`, `gc_ts[p]`, `live_count[p]`.
- **Order table:** `SETS × WAYS` entries `{valid, order_id, product, side, price, qty, oow}`.
- **Ladder:** `lq[p][side][i]` (uint32 aggregated qty), bitmap `bm[p][side][i]` = (`lq > 0`).
- **Strategy:** `fv[p]`, `edge[p]`, `fv_valid[p]`, `last_buy_px[p]`, `last_sell_px[p]` (sentinel `NONE`).
- **Risk:** `pos[p]` (int32, 0.1 MW), `last_order_ts` (uint64, initial 0), `has_ordered` (bool), `orders_out`, `next_coid`.
- **Counters:** `msgs_in, orders_out, rejects, err_unknown_type, err_bad_product, err_not_found, err_table_full, err_dup_id, err_oow, err_grid, err_seq_gap, err_qty_over, err_anchor, last_seq`. Also `first_t_in, last_t_in` (HW/SW only; not in golden).

### 6.3 Order table hashing (must be bit-exact)

```
fold(oid) = oid ^ (oid >> 10) ^ (oid >> 20) ^ (oid >> 30) ^ (oid >> 40) ^ (oid >> 50) ^ (oid >> 60)
set(oid)  = fold(oid) & (SETS - 1)
lookup:  the way w in set with valid && order_id == oid (at most one exists)
insert:  lowest-index way with !valid; none → err_table_full, drop the Add
remove:  valid = 0
```

### 6.4 Message processing (per message, in this order)

1. `msgs_in += 1`. If `last_seq != 0 && seq != last_seq + 1`: `err_seq_gap += 1`. Set `last_seq = seq`.
2. If type ∉ {A,X,E,M,S,V,H}: `err_unknown_type += 1`; stop.
3. If type ≠ H and `product ≥ P_MAX`: `err_bad_product += 1`; stop.
4. Dispatch:
   - **A (Add):** if lookup finds `oid` → `err_dup_id`, stop. Grid check: if `(price − anchor[p]) mod LADDER_TICK ≠ 0` → `err_grid`, stop (compute the remainder on exact integers; in Python use `(price - anchor) % LADDER_TICK != 0`, which is fine because only zero/non-zero matters). Insert (may fail → `err_table_full`, stop). `i = (price − anchor)/LADDER_TICK + W/2` (exact division). If `0 ≤ i < W`: `lq[p][side][i] += qty`, set bit; else mark entry `oow = 1`, `err_oow += 1`. `live_count[p] += 1`.
   - **X (Delete):** lookup; missing → `err_not_found`, stop. If not `oow`: `lq -= entry.qty`, clear bit if 0. Remove; `live_count[p] -= 1`.
   - **E / M (Execute / Reduce):** lookup; missing → `err_not_found`, stop. `r = min(qty, entry.qty)`; if `qty > entry.qty` → `err_qty_over += 1`. `entry.qty -= r`; if not `oow`: `lq -= r`, clear bit if 0. If `entry.qty == 0`: remove, `live_count[p] -= 1`.
   - **S (State):** if `new == OPEN && state[p] == PREOPEN`: if `live_count[p] == 0` → `anchor[p] = price`, `gc_ts[p] = order_id`; else `err_anchor += 1` (keep old anchor). If `new == PREOPEN` (slot reuse): require `live_count[p] == 0`, else `err_anchor += 1`; reset `fv_valid[p] = 0`, `pos[p] = 0`, `last_*_px[p] = NONE`. Set `state[p] = new`.
   - **V (Fair value):** `fv[p] = price`, `edge[p] = qty`, `fv_valid[p] = 1`, `last_buy_px[p] = last_sell_px[p] = NONE`.
   - **H:** nothing. If END flag: emit `'Z'` (and to `dbg_out` if `dbg_en`); stop.
5. **BBO** for product p: best_bid = highest set index in `bm[p][BID]`, best_ask = lowest set index in `bm[p][ASK]`; `price = anchor[p] + (i − W/2) * LADDER_TICK`, qty = `lq` at that index. If `dbg_en`: emit `'B'`.
6. **Strategy** (§6.5) → maybe a candidate → **Risk** (§6.6) → `'O'` or (if `dbg_en`) `'R'`.

**At most one candidate per input message.**

### 6.5 Strategy: fair-value taker

Evaluate only if **all** hold: `CTRL.strat_en`, `!CTRL.kill`, `state[p] == OPEN`, `fv_valid[p]`, `ts_ns + lockout_ms·10⁶ < gc_ts[p]`.

```
if ask_valid && best_ask <= fv[p] - edge[p] && best_ask != last_buy_px[p]:
    candidate = BUY  @ best_ask, qty = min(ask_qty, CLIP_QTY); last_buy_px[p]  = best_ask
elif bid_valid && best_bid >= fv[p] + edge[p] && best_bid != last_sell_px[p]:
    candidate = SELL @ best_bid, qty = min(bid_qty, CLIP_QTY); last_sell_px[p] = best_bid
```

`last_*_px` is updated even if risk later rejects (prevents reject storms).

### 6.6 Pre-trade risk (in order; first failure rejects)

| Step | Check | Action | Reason code |
|---|---|---|---|
| 1 | `abs(price − fv[p]) > COLLAR` | reject | 1 `COLLAR` |
| 2 | `qty = min(qty, MAX_ORDER_QTY)` | clamp | n/a |
| 3 | room = BUY: `MAX_POS − pos[p]`; SELL: `MAX_POS + pos[p]`; `qty = min(qty, room)`; if `qty ≤ 0` | reject | 2 `POSITION` |
| 4 | `has_ordered && ts_ns − last_order_ts < MIN_GAP_NS` | reject | 3 `RATE` |
| 5 | `orders_out ≥ MAX_ORDERS` | reject | 4 `MAX_ORDERS` |
| ok | emit `'O'`; `pos[p] ±= qty` (assume full fill, conservative); `orders_out += 1`; `last_order_ts = ts_ns`; `has_ordered = 1`; `coid = next_coid++` | n/a | n/a |

Rejects: `rejects += 1`; emit `'R'` only if `dbg_en`.

### 6.7 Runtime configuration (AXI-Lite; logical register map)

HLS generates the actual offsets. Generate `sw/app/t2t_regs.h` from the HLS driver header (`xt2t_core_hw.h`); the names below are authoritative.

| Name | Type | Default | Notes |
|---|---|---|---|
| `CTRL` | u32 | 0 | bit0 `strat_en`, bit1 `kill`, bit2 `dbg_en`, bit3 `soft_reset` (rising edge clears all state; IP deasserts TREADY while clearing; `STATUS.busy`) |
| `STATUS` | u32 (RO) | n/a | bit0 `busy` |
| `CLIP_QTY` | u32 | 50 | 5.0 MW |
| `MAX_ORDER_QTY` | u32 | 100 | |
| `MAX_POS` | i32 | 200 | 20 MW per product |
| `COLLAR` | u32 | 2000 | 20 EUR/MWh |
| `MIN_GAP_NS` | u32 | 0 | 0 disables |
| `MAX_ORDERS` | u32 | 1000000 | |
| `LOCKOUT_MS` | u32 | 0 | no orders within X ms of gate closure |
| `POS[p]` | i32 (RO) | n/a | |
| counters | u32 (RO) | n/a | all of §6.2 |

Golden runs store their config in `config.json` next to the dataset; every runner (Python, csim, board) reads the same file.

### 7.2 Generator model (`data/generator/`)

An event-driven simulation (priority queue keyed by ns timestamps, seeded RNG) that contains its own **price-time-priority matching engine** and emits the §5.2 feed.

**Products and slots**
- Each quarter-hour delivery period *d* has gate closure `GC_d = start_d − 60 min`. It is "active" during `[GC_d − 2h, GC_d]`.
- At most 8 products are active at once → map to slots `d mod 8`. Lifecycle per slot: `S(PREOPEN)` → `S(OPEN, anchor = round_to_grid(DA_d), gc_ts = GC_d)` → trading → at `GC_d`: `S(CLOSED)`, then `X` for every remaining order (the exchange purges the book) → slot reused by the next product.

**True fair value per product**
```
FV_d(t) = DA_d + w(t)·(IMB_d − DA_d) + Σ shocks_d(t)
w(t)    = logistic ramp 0 → 1 over the active window (configurable)
shocks  = at forecast-revision times: ΔFV = −β · Δwind_MW   (β default 0.02 EUR/MWh per MW)
```
Revision times: when real data is present, use the `Forecast5Hour`→`Forecast1Hour`→`ForecastCurrent` changes (place the 1-hour revision 5 min before GC; this approximation is documented). Plus Poisson minor revisions (rate configurable).

**Agents**
| Agent | Behavior | Key params |
|---|---|---|
| Market makers (N_mm) | Keep 1–3 levels each side around their *own* FV estimate (`FV + N(0,σ_mm)`); refresh after their reaction latency; cancel/replace on FV shocks | spread, size, reaction latency lognormal (median 200 ms) |
| Noise traders | Random aggressive orders crossing the spread; lognormal size (0.5–10 MW) | arrival rate λ(t) |
| Competitor takers (N_ct) | When a resting order is mispriced vs. true FV by > `edge_c`, take it after latency `L_c` (lognormal per agent, medians from 50 µs to 50 ms) | creates the latency race |
| Our slow path | Emits `V` messages: `FV + N(0,σ_model)` with delay `d_model` (default 200 ms) after each true-FV change; `edge` configurable | σ_model, d_model, edge |

Activity: `λ(t) = λ0 · (1 + a · exp(−(GC − t)/τ))` (rush to gate closure).
All prices snapped to the 0.10 EUR grid (documented simplification; the real tick is 0.01).

**Message emission**: crossing orders produce `E` messages for each resting order hit (no Add for the fully-filled aggressor; Add for any remainder); cancels → `X`; partial cancels → `M`. Every dataset ends with `H(END)`.

## 9. Hardware design

### 9.1 HLS IP `t2t_core` (`hls/`)

**Code structure** (mirrors the SysML logical blocks):
```
core/config.hpp        compile-time params (§6.1)
core/types.hpp         Msg, OutRec, enums, NONE sentinel
core/bitops.hpp        clz/ctz for 32-bit (loop form under __SYNTHESIS__, builtins otherwise)
core/order_table.hpp   4-way set-associative table (§6.3); each way a separate array → parallel read
core/price_ladder.hpp  lq arrays + 2-level bitmap (32×32-bit words + 32-bit summary) per (p, side); best-bid/ask search
core/strategy.hpp      §6.5
core/risk.hpp          §6.6
core/engine.hpp        process(msg, cfg, state, out) — pure function over a State struct; used by HLS top, csim, ARM SwEngine
t2t_top.cpp            HLS wrapper: reads 4 beats, captures TUSER on beat 0, calls engine, writes ≤4 beats per out stream
```

**Rules for synthesizable code:** C++14, fixed-width ints from `<cstdint>` (no `ap_int` needed in core), no dynamic memory, no recursion, no STL containers, bounded loops only, no floating point.

**Top-level interface:**
```cpp
void t2t_core(hls::stream<ap_axiu<64,32,0,0>>& md_in,    // TUSER[31:0] = t_in from axis_ts_in (beat 0)
              hls::stream<ap_axiu<64,0,0,0>>&  ord_out,
              hls::stream<ap_axiu<64,0,0,0>>&  dbg_out,
              /* s_axilite scalars: CTRL, CLIP_QTY, ..., counters (out) */);
#pragma HLS INTERFACE ap_ctrl_none port=return
#pragma HLS INTERFACE axis port=md_in
#pragma HLS INTERFACE axis port=ord_out
#pragma HLS INTERFACE axis port=dbg_out
#pragma HLS INTERFACE s_axilite port=... bundle=ctrl
#pragma HLS PIPELINE II=4
```
- One message per invocation; state in `static` arrays.
- Array partitioning: order-table ways → separate BRAMs; ladder `lq` per (p, side) → BRAM; bitmaps → LUTRAM/registers.
- `t_out` field written as 0; the RTL probe fills it.

**Targets** (must be reported from csynth/cosim):

| Metric | Required | Stretch |
|---|---|---|
| Clock | 100 MHz (10 ns), timing met post-route | 150 MHz |
| II per message | ≤ 4 cycles (= input line rate) | n/a |
| Fallback | If II=4 is infeasible: II ≤ 8 with written analysis of the critical loop-carried dependency | n/a |
| Latency (in → order out) | ≤ 64 cycles p99 | ≤ 32 cycles |
| Resources (Z7-10) | ≤ 70% LUT, ≤ 70% BRAM, timing closed | ≤ 50% |

Expected memory (Z7-10 has 60 × BRAM36 = 270 KB): order table ≈ 16 BRAM36, ladders ≈ 16 BRAM36, plus DMA FIFOs. Verify and record the actual numbers.

### 9.2 Testbench (`hls/tb/`)
- `tb_t2t.cpp`: reads `feed.bin` + `config.json`, drives `md_in` (synthetic TUSER = message index × 4 cycles), collects `ord_out`/`dbg_out`, writes `csim_orders.bin`, `csim_bbo.bin`, `csim_counters.json`, and calls the comparison (mask bytes 24..31). Exit code non-zero on mismatch (HLS csim/cosim convention).
- `test_core.cpp`: unit tests for order_table (collisions, full set, remove/reinsert), ladder (best search at edges 0 and W−1, negative prices, OOW), strategy (dedup, lockout), risk (each reason code), protocol pack/unpack.
- **Shim** (`hls/shim/`): minimal `hls::stream<T>` (std::deque) and `ap_axiu` structs, so CI builds csim with plain g++ when Vitis isn't installed. With Vitis, use the real headers.

### 9.3 RTL probes (`rtl/`)
| Module | Function |
|---|---|
| `ts_counter.v` | Free-running 64-bit cycle counter, sync reset |
| `axis_ts_in.v` | Pass-through AXIS (DMA MM2S → IP). Counts beats mod 4 (reset on TLAST and on reset). On the beat-0 handshake drives `TUSER = counter[31:0]`. Zero added latency (combinational sideband) |
| `axis_ts_out.v` | Pass-through AXIS (IP `ord_out` → DMA S2MM). Counts beats mod 4. On the beat-3 handshake replaces `TDATA[63:32]` with `counter[31:0]` (= `t_out`). Preserves TLAST/TKEEP. Zero added latency |

`latency_cycles = (t_out − t_in) mod 2³²`.
Tests: cocotb + Icarus with random backpressure; verify timestamps, beat alignment, TLAST passthrough.

### 9.4 Vivado block design (`hw/build_bd.tcl`)
- Board: Digilent Zybo Z7-10 board files (`digilent/vivado-boards`); the script fails clearly if they are missing.
- IP: `processing_system7` (board preset; FCLK_CLK0 = 100 MHz; HP0 enabled; GP0 master; IRQ_F2P), `axi_dma_0` (MM2S + S2MM, simple mode, 64-bit stream, buffer length width 26), `axi_dma_1` (S2MM only, for `dbg_out`), `axis_ts_in`, `axis_ts_out`, `ts_counter`, `t2t_core`, SmartConnect/Interconnect, `proc_sys_reset`, `xlconcat` for interrupts. Optional ILA behind a `-ila` flag.
- Outputs: bitstream, `dk1_t2t.xsa`, utilization + timing reports copied to `hw/reports/`.
- Note: AXI DMA max transfer = 64 MB − 1 (26-bit length) → the PS sends the input in chunks (§10).

## 10. Software (PS) design (`sw/`)

### 10.1 Platform
Bare-metal standalone BSP (or FreeRTOS via OSAL), Cortex-A9 @ 667 MHz, caches on. Libraries: `xilffs` (SD FAT32), `XAxiDma`, `XTime` (global timer at CPU/2 ≈ 333 MHz), UART.

### 10.2 Application components (C++)
| Component | Responsibility |
|---|---|
| `DatasetLoader` | Read `feed.bin` + `config.json` (minimal JSON parser or a tiny key=value companion file generated by Python) from SD into a 64-byte-aligned DDR buffer; validate size % 32 == 0 |
| `ConfigManager` | Apply config to IP registers; soft reset; read counters/positions |
| `T2tProxy` | **Hardware Proxy** around the IP's AXI-Lite registers (only place that touches register addresses) |
| `DmaChannel` | Wraps XAxiDma: arm S2MM (one transfer until TLAST), send MM2S in ≤ 32 MB chunks back-to-back, cache flush/invalidate |
| `SessionController` | State machine (Idle → Loaded → Configured → Running → Draining → Done/Error); timeouts |
| `SwEngine` | **Architecture A baseline:** runs the *same* `core/engine.hpp` on the ARM over the DDR buffer, stamping `t_in`/`t_out` with `XTime` (lower 32 bits, global-timer ticks); output format identical to HW |
| `ResultWriter` | Writes `orders_hw.bin`, `dbg_hw.bin`, `orders_sw.bin`, `counters_hw.json`, `run_info.json` (clock frequencies, timer rates, wall times) to SD |
| `Cli` | UART commands: `ls`, `load <dir>`, `cfg show`, `cfg set <k> <v>`, `run hw`, `run sw`, `run both`, `stats`, `kill`, `reset` |

### 10.3 OSAL and the course's Two-Part Architecture
- `sw/osal/` defines a small interface (`Thread`, `Mutex`, `Queue<T>`, `Timer`, `Clock`). The default implementation is bare-metal (single-threaded, interrupt-driven DMA completion). If the course OSAL package is provided (A4), add an adapter so the app uses it. Document which one was used.
- **Two-Part Architecture mapping** (align the terminology with the course material in the report): **Part 1, hard real-time:** the PL fast path (`t2t_core` + probes + DMA streaming). **Part 2, soft/non-real-time:** the PS control, configuration, dataset I/O, logging, CLI, and the fair-value slow path.

### 10.4 Design patterns to apply and justify (document in `05_sw_design_patterns.md`)
| Pattern | Where | Why |
|---|---|---|
| Hardware Proxy | `T2tProxy`, `DmaChannel` | Isolates register/driver details; enables a mock for host tests |
| Adapter | OSAL over bare-metal / course OSAL | Portability |
| State | `SessionController`; product state in core | Explicit, testable lifecycles (matches the SysML state machines) |
| Strategy | `IEngine` with `HwEngine` / `SwEngine` implementations (and swappable trading-strategy functions in the core) | Same session code runs Arch A or C; fair comparison |
| Observer | Session events → `ResultWriter`, `Cli` progress | Decoupled reporting |
| Command | CLI commands | Extensible, testable command handling |
| Queuing / ring buffer | DMA chunk scheduling | Bounded memory, no dynamic allocation |

Host-side unit tests (g++ on PC) for `SessionController`, `Cli` parsing and `SwEngine` with a mocked proxy.

### 10.5 Measurement procedure (board)
1. `run hw` with `dbg_en=0` → throughput and latency. 2. `run hw` with `dbg_en=1` (datasets ≤ 1.5M msgs because of the 64 MB S2MM limit) → full BBO-trace verification. 3. `run sw` → baseline. 4. Copy the SD outputs to the PC → `tools/compare.py` + `tools/analyze.py`.

Throughput (HW): `msgs_in / ((last_t_in − first_t_in)/F_clk)` from the `'Z'` record (fabric input rate), plus wall-clock msgs/s including DMA chunk gaps from `XTime`. Report both.

## 16. Known risks and mitigations

| Risk | Mitigation |
|---|---|
| II=4 not met due to the ladder read-modify-write / bitmap loop-carried dependency | Forwarding registers for the last-updated level; split the bitmap update and the best search across stages; fallback II ≤ 8 with analysis |
| BRAM over budget on Z7-10 | Reduce `P_MAX` to 4 or `W` to 512 (update the generator anchor window); document |
| Timing at 100 MHz fails in the priority encoder | Register the summary word; 2-cycle best search |
| Generator too slow for multi-million datasets | Profile; numba for the matching engine; generate per-slot in parallel then merge by timestamp |
| DMA limits (64 MB per transfer) | Chunked MM2S; dbg runs ≤ 1.5M msgs |
| Course requires a specific UML tool | PlantUML sources are the model; redraw in EA from them |
| Vendor tool version differences | Tcl scripts parameterized by version; note the tested version in README |
